# Domain docs

This repo uses a single-context layout:
- `GLOSSARY.md` at the root for domain vocabulary.
- `docs/adr/` for architecture decisions.

Before exploring the codebase, read the glossary and ADRs relevant to
the work. If they do not exist, proceed silently. Domain-modeling work
creates them when terms or decisions are resolved.

Use glossary terms consistently in issues, proposals, code and tests.
Surface conflicts with an ADR explicitly, naming the decision and
explaining why it may need revisiting.
