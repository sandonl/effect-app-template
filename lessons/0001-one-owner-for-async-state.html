One owner for async state

The move from TanStack Query to Effect Atom was not mainly a syntax change. It removed a second lifecycle system from an already Effect-shaped request.

The old path had two owners

  1. React component
  2. TanStack query
  3. Promise bridge
  4. Managed runtime
  5. Effect HTTP API

TanStack Query owned loading, caching, retries, cancellation, and refresh. Effect owned the typed request and fiber. The adapter had to translate TanStack's AbortSignal and Promise contract into Effect runtime execution. Neither library was being misused—but the application had to reconcile two valid lifecycle models.

The new path has one owner

  1. React component
  2. Atom hook
  3. Atom registry
  4. Atom HTTP API
  5. Effect HTTP API

AtomHttpApi.Service derives a client, query constructors, and mutation constructors from the shared HTTP API contract. The registry mounts the query atom, runs its Effect, stores an AsyncResult, interrupts work when appropriate, and cleans up registry-owned resources.

Key correction: there is still an Effect runtime. We stopped constructing and disposing it in application glue. Effect Atom now encapsulates that mechanism behind the query abstraction.

Read the current scaffold as three declarations

1. Declare the client capability

export class AppApiClient extends AtomHttpApi.Service<AppApiClient>()(
  "AppApiClient",
  {
    api: AppApi,
    baseUrl: globalThis.location.origin,
    httpClient: BrowserHttpClient.layerFetch,
  },
) {}

This says which contract and HTTP implementation make up the browser client. It does not eagerly perform the health request.

2. Declare one request as an atom

export const healthAtom = AppApiClient.query(
  "health",
  "check",
  {},
);

The group and endpoint names come from AppApi. A typo or invalid request shape is a type error.

3. Let React observe the state machine

const health = useAtomValue(healthAtom);

switch (health._tag) {
  case "Initial": // no result yet
  case "Failure": // a Cause is available
  case "Success": // health.value is typed
}

Unlike several independent booleans, AsyncResult is a discriminated union. The impossible combination “success and error at once” cannot be represented.

Atom versus TanStack Query

Decision Effect Atom TanStack Query
Best fit Effect services and typed Effect HTTP APIs end to end Mixed Promise-based clients and broad server-state tooling
Async state AsyncResult and atoms Query result objects and query cache
Execution Registry-managed Effect fibers Promise-returning query functions
Cancellation Effect interruption AbortSignal passed to the query function
Maturity Effect v4 beta and unstable namespace Established, framework-focused ecosystem

TanStack Query remains an excellent choice. The rule is coherence: choose one owner for the same remote state. Do not put an Atom query inside a TanStack query merely to gain both APIs.

Retrieval practice

Who owns the lifetime?

Without looking above, answer: when HealthStatus unmounts, which object knows that the health atom has lost a React subscriber, and which layer actually runs or interrupts its Effect?

Reveal the answer

The registry tracks the subscription and atom lifetime. The Atom runtime created behind AppApiClient runs the Effect using the registry-managed scope. React only subscribes through the hook.
