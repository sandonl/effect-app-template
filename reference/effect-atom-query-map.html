Effect Atom query map

The smallest coherent path from a shared Effect HTTP API contract to rendered React state.

Concern Owner This repository
Schema and endpoint Shared HTTP API package packages/http_api/src/health_api.ts
Browser transport Atom HTTP API service apps/web/src/api_client.ts
Request identity Query atom features/health/health_atoms.ts
State and lifecycle Atom registry app/app_providers.tsx
Rendering Feature component features/health/health_status.tsx

Adding a read endpoint

  1. Add its schemas and endpoint to the shared HTTP API.
  2. Implement the server handler against that same contract.
  3. Create a feature atom with AppApiClient.query.
  4. Read it with useAtomValue.
  5. Render every relevant AsyncResult case.

Guardrails

  • Do not call Effect.runPromise in feature components.
  • Do not create a runtime per request or component render.
  • Do not duplicate the same remote state in two cache systems.
  • Do not treat Atom TTL as TanStack Query stale time.
  • Do pin all Effect v4 packages to one compatible version.

Choosing the other path

Prefer TanStack Query when most clients are Promise-native, its cache policy and devtools are central product needs, or Effect is only an isolated implementation detail. In that design, keep one application ManagedRuntime and one explicit Effect-to-Promise adapter.
